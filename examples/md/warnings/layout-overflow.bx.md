# 1枚に詰め込みすぎた論点

- 第1世代は **2029年12月** に保守が切れるため、それまでに移行先を決める
- 第2世代以降は、いまのランタイムを続けるか新しい OS へ移るかを選べる
- 移行の検証には、少なくとも半年の並行稼働の期間を見込む
- 検証の環境は、本番と同じ構成のものを別に用意する
- 料金の更新は年に2回あり、更新の前に継続か移行かを決める必要がある

:::::compare
::::option いまのランタイムを続ける
:::pros
- 既存の運用手順をそのまま使える
- 教育の費用がかからない
:::
:::cons
- 料金の更新のたびに費用が上がる
- 第1世代では保守の期限を越えられない
:::
::::
::::option 新しい OS へ移る
:::pros
- 長い期間の保守が受けられる
- 構成を新しく揃えられる
:::
:::cons
- 移行の期間と検証の環境が要る
- 運用手順を書き直す必要がある
:::
::::
:::::

- 判断の期限は次の料金の更新の3か月前とする
- 決めた結果は運用の会議で共有する
- 移行する場合は、世代ごとに切り替えの順番を決める
- 切り替えの前に、戻すための手順を用意して試しておく
- 並行稼働の間は、両方の環境の監視を続ける
- 移行が終わった世代から、古い環境の契約を順に止める
- 止めた環境の記録は、決めた期間だけ残しておく

:::note
期日と数値はすべて架空のもの
:::
